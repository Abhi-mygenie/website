Context — What Happens When a Demo is Booked

When a user books a demo through the Calendly widget, two paths fire to update the Freshsales contact:

Path 1 — Client-side (immediate, from browser)

User picks Calendly slot
→
DemoForm.jsx markBooked()
→
POST /api/demo-booked
→
freshsales.mark_demo_booked()

Path 2 — Calendly Webhook (async, from Calendly servers)

Calendly fires invitee.created
→
POST /api/calendly/webhook
→
freshsales.mark_demo_booked()
→
+ Meet link + Demo time

What mark_demo_booked() Sets in Freshsales

FieldValueSource
contact_status_id402001331872 = "Follow up for scheduling demo"Env: FRESHSALES_STATUS_DEMO_BOOKED_ID
Tag added"Follow up for scheduling demo"Env: FRESHSALES_DEMO_BOOKED_TAG
lifecycle_stage_id403021121245 (Lead)Env: FRESHSALES_LIFECYCLE_DEMO_BOOKED_ID
cf_meeting_linkGoogle Meet URLPath 2 only (webhook)
cf_channel_manager_nameDemo time in ISTPath 2 only (webhook)
Important: Path 2 (webhook) only fires if CALENDLY_WEBHOOK_CALLBACK_URL is set and the webhook is registered in Calendly. If empty, only Path 1 fires — and it does NOT set meet link or demo time.

Check Calendly Webhook Registration

Verify whether a webhook is actually registered in Calendly pointing to your production URL:

cd /var/www/website/backend
python3 -c "
from dotenv import load_dotenv; load_dotenv('.env')
import httpx, os
token = os.environ.get('CALENDLY_API_TOKEN')
r = httpx.get('https://api.calendly.com/users/me',
    headers={'Authorization': f'Bearer {token}'})
user = r.json()
org = user['resource']['current_organization']
print('Org:', org)

r2 = httpx.get('https://api.calendly.com/webhook_subscriptions',
    params={'organization': org, 'scope': 'organization'},
    headers={'Authorization': f'Bearer {token}'})
hooks = r2.json().get('collection', [])
print(f'Registered webhooks: {len(hooks)}')
for h in hooks:
    print(f'  URL:    {h[\"callback_url\"]}')
    print(f'  State:  {h[\"state\"]}')
    print(f'  Events: {h[\"events\"]}')
    print()
if not hooks:
    print('WARNING: No webhooks registered!')
    print('Path 2 (Calendly webhook) will NOT fire.')
    print('Meet link + demo time will NOT be written to Freshsales.')
"
Expected: At least 1 webhook pointing to https://www.mygenie.online/api/calendly/webhook with state active
If 0 webhooks: Set CALENDLY_WEBHOOK_CALLBACK_URL=https://www.mygenie.online/api/calendly/webhook in .env, restart the backend. The startup code (_sync_calendly_webhook) will auto-register it.

Live Test — Submit a Demo Lead End-to-End

Open a browser to https://www.mygenie.online and complete the full flow:

  1. Fill the demo form (use a test name + your real phone for OTP)
  2. Enter OTP code
  3. Pick a Calendly slot and confirm booking

While doing this, watch the backend logs in another terminal:

# Terminal 2 — watch logs live
tail -f /var/log/mygenie-api*.log 2>/dev/null | grep -iE "demo-booked|demo_booked|mark_demo|calendly|webhook|Freshsales"

# If logs are in journalctl instead:
journalctl -u mygenie-api -f | grep -iE "demo-booked|demo_booked|mark_demo|calendly"
Expected log entries:
1. POST /api/demo-booked (client-side path)
2. Calendly invitee.created processed email=... contact=... (webhook path, if registered)
No Freshsales 400/500 errors.
If no log entries appear: The POST isn't reaching the backend. Check browser DevTools Network tab for failed /api/demo-booked request. Common causes: CORS, wrong REACT_APP_BACKEND_URL, or network error.

Verify Freshsales Contact Was Updated

After the test booking, check if the contact's status changed in Freshsales:

# Find the test lead in MongoDB
cd /var/www/website/backend
python3 -c "
from dotenv import load_dotenv; load_dotenv('.env')
from pymongo import MongoClient
import os
client = MongoClient(os.environ.get('MONGO_URL'))
db = client[os.environ.get('DB_NAME')]

# Replace with your test name
doc = db.demo_requests.find_one(
    {'name': {'\\$regex': 'YOUR_TEST_NAME', '\\$options': 'i'}},
    {'_id':0, 'name':1, 'freshsales_contact_id':1, 'status':1,
     'demo_booked_at':1, 'meet_link':1, 'demo_at':1},
    sort=[('created_at', -1)])
print(doc)
"
Expected:
status: 'demo_booked'
freshsales_contact_id: 402XXXXXXXXX (not None)
demo_booked_at: '2026-07-...'
meet_link: '...' (only if webhook fired)
demo_at: '26 Jul 2026, ...' (only if webhook fired)
If freshsales_contact_id is None: Freshsales upsert_contact failed during form submission. Check logs for Freshsales create 400 or Freshsales upsert error.
If status is not 'demo_booked': The POST /api/demo-booked didn't execute. Check browser console for errors.
If meet_link is missing: Calendly webhook didn't fire. Go back to Step 3.

Verify in Freshsales CRM

Open the test contact in Freshsales and confirm:

  • Status = "Follow up for scheduling demo"
  • Tag "Follow up for scheduling demo" is present
  • Tag "OTP-Verified" is present
  • Custom field cf_meeting_link has the Google Meet URL (webhook path only)
  • Custom field cf_channel_manager_name has the demo date/time (webhook path only)
If status is still "New": mark_demo_booked() failed silently. Most common cause: Freshsales API rejected the contact_status_id write. Check logs for Freshsales demo-booked 400.
If tag is "Demo Scheduled (Web)" instead of "Follow up for scheduling demo": Backend was not restarted after .env change. Run systemctl restart mygenie-api.service.

Manual API Test (bypass frontend)

If the frontend test is unclear, call the API directly to isolate backend issues:

# Test with a known Freshsales contact ID
curl -s -X POST https://www.mygenie.online/api/demo-booked \
  -H "Content-Type: application/json" \
  -d '{
    "freshsales_contact_id": 402213582497,
    "email": "test@example.com",
    "lead_id": null
  }' | python3 -m json.tool
Expected: {"ok": true, "freshsales_contact_id": 402213582497}
Then check the contact in Freshsales — status should now be "Follow up for scheduling demo".
If returns {"ok": true, "freshsales_contact_id": null}: Contact not found. Verify the ID exists in Freshsales.
If returns 500 error: Check backend logs immediately.

Status stays "New" after booking mark_demo_booked() not firing or failing Check backend logs for errors. Verify POST /api/demo-booked reaches backend.
Tag shows "Demo Scheduled (Web)" instead of "Follow up for scheduling demo" Backend loaded before FRESHSALES_DEMO_BOOKED_TAG was added to .env systemctl restart mygenie-api.service

Works in preview/UAT but not production Different .env, different code version, or backend not restarted Compare .env files, deploy latest code, restart service
