## 1. What This Codebase Is

MyGenie POS — a React marketing website for a restaurant POS product sold in India.
The site is optimised for Google Ads Quality Score and organic SEO.

**Stack:**
- Frontend: React 19 + CRA/CRACO + Tailwind CSS
- Serve mode: `node scripts/static-server.js` serving prerendered `build/` directory on port 3000
- Backend: FastAPI (uvicorn) on port 8001, remote MongoDB at 52.66.232.149
- Prerender: Puppeteer (`scripts/prerender.js`) — runs AFTER every build to snapshot 57 routes

**Critical build flow — do not skip steps:**
```bash
cd /app/frontend
npx craco build                          # ~60s — compiles React
node scripts/prerender.js                # ~5-6 min — Puppeteer snapshots 57 routes
sudo supervisorctl restart frontend      # serves the new build
```
The static-server serves `build/` directory. If you skip the build/prerender, changes will not be live.

## 5. Critical Technical Rules — Do Not Break

### Build system
- Every source change requires: `npx craco build` → `node scripts/prerender.js` → `sudo supervisorctl restart frontend`
- Hot-reload only works for source files while the dev server is running in `craco start` mode — the PRODUCTION supervisor runs `yarn start` which serves static `build/`. Code changes do NOT hot-reload in production.
- Check build log: `tail -f /app/frontend/prerender_cr179.log`

### GTM / Conversion Events — SACRED
```
Stage 1: Form submit → pushLead("form_submitted") → GTM: form_submitted ₹0
Stage 2: OTP verify  → pushLead("book_demo")      → GTM: thankyou_conversion ₹200  ← DO NOT MOVE
Stage 3: Calendly    → navigate("/thank-you")      → GTM: (no direct event)
```
The `thankyou_conversion` GTM event fires at Stage 2 (OTP) — NOT at Calendly. Owner confirmed this is intentional. Never move it. DemoForm.jsx ~line 294.

### CMS Override System
The site has a CMS layer. Content displayed to visitors comes from:
1. **MongoDB CMS store** (if a key is stored) — takes priority
2. **Fallback in data file** (if no CMS key stored) — used otherwise

Current CMS keys stored (from live API check):
- `home.hero.banner_image` — hero image (no-op, same as fallback)
- `home.testimonials` — testimonials array
- `home.trust_logos` — logo list
- `sector.*.faqs` — FAQs for all sector pages (restaurants, cafes, cloud-kitchens, hotels-resorts, chains, qsr, food-courts, canteens, bars-pubs, bakeries, ice-cream-desserts)
- `product.sell-serve.faqs`, `product.sell-serve.video` — sell-serve FAQs and demo video
- `pricing.plans`, `pricing.addons` — pricing data
- `product.run-property.hero.h1`, `product.run-property.hero.sub` — run-property page hero

**Implication:** Changes to sector/product `faqs` arrays in data files will NOT show — CMS overrides them. Changes to `h1`, `sub`, `pains`, `solutions`, `modules`, `proof` fields ARE safe — none are stored in CMS.

### Template Architecture
- Sector pages (`/solutions/*`) → `SectorPage.jsx` + data from `sectors.js`
- Product pages (`/product/*`) → `ProductPage.jsx` + data from `products.js`
- Never edit SectorPage.jsx or ProductPage.jsx for per-page content — change the data files

### Product page title formula:

## 10. Prerendering Facts

- `prerender.js` uses Puppeteer to visit 57 routes and snapshot them
- It waits for `[data-testid$="-page"]`, `[data-testid$="-hero"]`, or `[data-testid="hero"]` before capturing
- New pages need `data-testid="<slug>-page"` to be captured (e.g., `thank-you-page`)
- After prerender, all meta tags (title, canonical, og:title, etc.) are deduplicated — only the helmet-injected version survives
- New routes added to prerender: add to `extraRoutes` array in `scripts/prerender.js` line 13
- Current extraRoutes: `["/demo", "/payment-success", "/404", "/thank-you"]`
