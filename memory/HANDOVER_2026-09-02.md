## 1. What This Codebase Is

MyGenie POS — a React marketing website for a restaurant POS product sold in India.
Optimised for Google Ads Quality Score, organic SEO, and Core Web Vitals.

**Stack:**
- Frontend: React 19 + CRA/CRACO + Tailwind CSS
- Serve mode: `node scripts/static-server.js` serving prerendered `build/` directory on port 3000

**Critical build flow — never skip:**
```bash

sudo supervisorctl restart frontend  # serves the new static build
```
Hot-reload does NOT work in production — supervisor runs `yarn start` = static server. Code changes only go live after a rebuild.

### CR-183 — Poppins 500 + 600 Not Preloaded ✅
**File:** `public/index.html` — 2 lines added after existing Poppins 400 preload

**What:** Added `<link rel="preload">` for `poppins-500.woff2` and `poppins-600.woff2`.

```html
<link rel="preload" as="font" type="font/woff2" crossorigin href="/fonts/poppins-500.woff2" />
<link rel="preload" as="font" type="font/woff2" crossorigin href="/fonts/poppins-600.woff2" />
```

Poppins uses `font-display: optional` — without a preload, 500/600 arrived at 1,486ms, past the optional window, so the browser used Poppins Fallback (metric-matched Arial) for the entire session. Now they load on time.
Poppins 700 skipped (H1 uses Clash Display, not Poppins).

## 7. Critical Technical Rules — Do Not Break

### Build system
- `yarn start` = static server. Code changes DO NOT hot-reload in production.
- Every change requires: `cd /app/frontend && yarn build` → `sudo supervisorctl restart frontend`
- Build takes ~3 minutes (craco ~60s + Puppeteer prerender 57 routes ~2 min)

### GTM Conversion Events — SACRED, do not move
```
Stage 1: Form submit     → pushLead("form_submitted")  → GTM: form_submitted ₹0
Stage 2: OTP verify      → pushLead("book_demo")        → GTM: thankyou_conversion ₹200  ← DO NOT MOVE
Stage 3: Calendly booked → navigate("/thank-you")       → (no separate GTM event)
```
`thankyou_conversion` fires at OTP stage (Stage 2) — owner confirmed intentional.

### CMS Override System
Certain fields are overridden in MongoDB CMS. Current live overrides:
```
home.trust_logos       home.testimonials      home.hero.banner_image
sector.*.faqs (all)    product.run-property.hero.sub
product.sell-serve.faqs  product.sell-serve.video
pricing.plans          pricing.addons         customers.stats
```
Changes to these data file fallbacks will NOT show — CMS takes priority. For unregistered keys (e.g., `home.hero.sub`, sector `h1/sub/pains/solutions`), data file changes ARE safe.

### `sub` field dual-use
`SectorPage.jsx` and `ProductPage.jsx` use `s.sub`/`p.sub` as BOTH the meta description AND the visible hero subtitle. CR-181 trimmed these to ≤160ch — always keep in mind when editing sector/product data files.

### Template architecture
- Sector pages: edit `src/data/sectors.js` only — never touch `SectorPage.jsx` for per-page content
- Product pages: edit `src/data/products.js` only — never touch `ProductPage.jsx`

### Schema type — QAPage not FAQPage
- Google retired `FAQPage` rich results on May 7, 2026 (per CR-106, confirmed via web search)
- All new FAQ schemas use `"@type": "QAPage"` — per CR-106 precedent
- LP pages (RestaurantBillingSoftware, PetpoojaAlternative etc.) still have `FAQPage` — harmless, do not urgently change

### Form name attributes — not required
DemoForm uses React state + `axios.post()`. The HTML `name=` attribute is NOT needed. Previous auditors flagged this incorrectly twice. Do not add `name=` attributes — it is not a bug.
