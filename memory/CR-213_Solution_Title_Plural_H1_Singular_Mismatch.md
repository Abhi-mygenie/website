# CR-213 — Solution Pages: Title Tag Plural vs H1 Singular Keyword Mismatch

**Registered:** 2026-09-05
**Source:** ISS-C — keyword consistency audit across all 11 solution pages
**Status:** 🔲 Open — Ready to implement
**Priority:** P2 (SEO refinement — not a blocker)
**Owner:** Agent (code + rebuild)
**Files:** `src/data/sectors.js` (add `nameSingular` field) · `src/pages/SectorPage.jsx` (use it in title formula)

## 1. Problem

All 11 solution page title tags are generated by `SectorPage.jsx:62`:
```js
const seoTitle = `${s.name} POS System & Billing Software | MyGenie`;
```

`s.name` is always the **plural / brand display form** (e.g. "Restaurants", "Cafés", "Bars & Pubs").
The `h1` field in `sectors.js` uses **singular / category form** (e.g. "Restaurant POS system", "Café POS system", "Bar POS system").

**Result: all 11 pages have a plural-singular mismatch between title and H1.**

|---|---|---|

| qsr | QSR / Fast Food | QSR |

## 2. SEO Impact

Google uses `<title>` and `<h1>` as independent relevance signals. They don't need
to be identical, but keyword consistency between them strengthens the page's relevance
score for a given query.

**Example:** A user searches "restaurant POS system" (singular).
- H1: "Restaurant POS system & billing software…" → exact match ✅
- Title: "Restaurants POS System & Billing Software…" → plural mismatch ❌

Google's algorithm handles singular/plural as near-equivalent, but the mismatch creates
a small relevance dilution. Aligning both to singular form makes the keyword signal consistent
across both elements.

**Priority: P2** — this is a refinement. Current pages rank and convert. This is a
marginal improvement to click-through and relevance scoring, not a critical fix.

## 3. Chosen Fix — Option A: Add `nameSingular` field to sectors.js

**Why Option A:**
- Doesn't touch the existing carefully-crafted H1 fields (CR-187 work preserved)
- `s.name` is used in many places beyond the title (nav dropdowns, `h2` headings, DemoForm sector param, breadcrumb schema, JSON-LD). Changing `s.name` risks visual regressions.
- Adding a dedicated `nameSingular` field is clean and future-proof
- `seoTitle` formula uses `nameSingular` only — a single-line change in `SectorPage.jsx`

**Files touched:**
1. `src/data/sectors.js` — add `nameSingular` to each of 11 sector objects
2. `src/pages/SectorPage.jsx` line 62 — use `s.nameSingular || s.name` in formula

## 5. Exact Edits

### Edit A — `SectorPage.jsx` (1 line)

**File:** `src/pages/SectorPage.jsx` line 62

```
BEFORE:
  const seoTitle = `${s.name} POS System & Billing Software | MyGenie`;

AFTER:
  const seoTitle = `${s.nameSingular || s.name} POS System & Billing Software | MyGenie`;
```

**Fallback `|| s.name`**: ensures zero regression if any sector is missing `nameSingular`.
